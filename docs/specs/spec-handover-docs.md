## 1. 管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 根 `README.md` 重写；新增 `docs/handover.md`；`docs/decisions/README.md` 补一览表 | spec 与 ADR 的**正文**（要改正文另走「改旧 spec 卡」，本份一个字不动） |
| `docs/specs/` 各文件的**头部元信息行**回填（Issue 号、实施状态）；根 `AGENTS.md` 第 5 行的陈旧状态句（只这一句） | 代码（`backend/`、`frontend/`）、`deploy/` 文档正文、issue 内容 |

`AGENTS.md` 在 spec-s1a 里列为 S1-A 的**独占**目录（`spec-s1a-foundation.md` §2）。S1-A 已合并（PR #13），独占是并行期的保护、已不再是常设禁令；而该行「`frontend/`（React，S1-E 未开工）」正是本份要消灭的那类陈旧状态句——交接人翻 `AGENTS.md` 一样会读偏。故并入改动面，**只回填这一句**，其余一字不动。

本 spec 自带一条 ADR（[ADR-20261007-handover-s2-first](../decisions/2026-10-07-handover-s2-first.md)）——按项目规矩「拍板命中写入条件即与 spec 放同一个文档 PR」随本 PR 一起落，**不属下方实施 issue 的范围**。

## 3. 两层结构（本份的核心决定）

| 层 | 文件 | 给谁 | 到什么程度算够 |
|---|---|---|---|
| 门口 | `README.md` | 任何人，第一眼 | 10 分钟看懂：是什么 / 为什么 / 现在到哪 / 下一步按哪几个键 |
| 内部 | `docs/handover.md` | 接手的非技术 owner | 照着能独立推进：上线、日常操作、S2 要什么、活怎么交代出去 |

技术细节（总纲、ADR、`backend/ARCHITECTURE.md`、`deploy/install.md`）**不进这两层正文**——一律链出去，正文不复述（复述必漂）。

## 4. 要做的事

### 4.1 重写根 `README.md`

节序（非技术主线）：

1. **一句话**：这个系统替谁干什么。
2. **前因后果**（≤ 10 行）：业务背景（10+ 店、日 200–1000 单）、为什么自研（现成 ERP 采购环节全是半自动）、谁拍板；链 Issue #1 全文与 [ADR-build-in-house](../decisions/2026-10-07-build-in-house.md)。
3. **现在到哪了**：S1 六份全部合并、全部「待上线」；**当前唯一卡点 ＝ S1-C（#8）挂「受阻」**（等 1688 买家自用版权限批下来），#20（S1-D 白屏修复）也还没关。**上线前置 5 项照总纲 §12.1 列全**（1688 权限 / Ozon 凭据 / 中转点 / 服务器+域名+线路 / 合规），不缩写成「三件事」。
4. **怎么用起来**：上线梗概——要买什么、要准备哪些账号与凭据、大概多久、卡住看哪 → 链 `docs/handover.md` §4。
5. **文档地图**：谁看哪份——非技术看 handover；技术看总纲 / ADR / `backend/ARCHITECTURE.md` / `deploy/`。
6. **这个仓怎么干活**：spec-flow 两段流程、ADR、issue 标签，各**一句话** + 指回 `AGENTS.md`（不复述细则）。

### 4.2 新增 `docs/handover.md`

节序：

1. **这个系统是什么**——非技术版前因后果，带一个生活化比方。
2. **术语表**——正文出现的每个内部专名一句话解释（rFBS / FBP / 本土店、中转点 / 货代仓、面单、`posting_number`、采购任务、异常池、凭据保险箱、追踪号回填……）；按正文首次出现顺序排。
3. **现在到哪了**——S1 六份各做了什么 × 状态表；状态逐份照 issue 标签写（含 S1-C 的「受阻」及原因），不合并成一句「全部待上线」；上线前置 5 项照总纲 §12.1。
4. **从零上线**——`deploy/install.md` 的「人话版」：要买什么、要准备哪些账号与凭据、每步大概多久、卡住看哪；命令细则**链过去，不复述**。
5. **日常怎么用**——对着操作台页面写（订单 / 采购任务 / 发货 / 映射与报价 / 异常池 / 店铺与凭据）。
6. **S2 要做什么**——总纲 §9·S2 验收清单翻成人话 + 「怎么算干完了」。
7. **活怎么交代出去**——非技术 owner 找人 / 找 AI 接着干的最小流程：需求怎么描述、issue 怎么用、每份交付物合并前要谁点头、去哪看进度。
8. **出了事怎么办**——凭据到期告警、备份与恢复演练、日志在哪、看哪张表。

### 4.3 `docs/decisions/README.md` 补 ADR 一览表

一张表，一条 ADR 一行：链接 + 状态 + 一句话。**状态必须与各文件头部一致**；已被取代的（`go-package-deps` v1）也列，标「已被取代」。排规则页「载体分工」之后，不动规则正文。

### 4.4 陈旧状态行回填（纯机械）

| 文件 | 现状 | 改成 |
|---|---|---|
| 总纲 | `Issue: 待开（…届时回填号）` | 回填 S1 实施 issue 号（#6 ~ #11），写明「S1 已实施，见各子 spec」 |
| spec-s1d | `跨份验收与协作声明：S1 父 issue（待开）` | `#5` |
| spec-s1f | `Issue: 待开`、`跨份验收与协作声明：S1 父 issue（待开）` | `#11`、`#5` |

| 根 `AGENTS.md` | 第 5 行「`frontend/`（React，S1-E 未开工）」 | 「`frontend/`（React，S1-E 已合并，待上线）」——**只改这一句**，别的一字不动 |

## 5. 机制清单

| # | 机制 | 解决什么 / 没有它会怎样 |
|---|---|---|
| 1 | README 重写（门口层） | 解决「第一眼就看过时信息、直接走偏」；没有它：交接人读了 README 以为项目才开工一半 |
| 2 | 新增 `docs/handover.md`（内部层） | 解决「非技术 owner 拿到仓库没法独立推进」；没有它：README 只够给梗概，真上手还得满仓翻 |
| 3 | 「技术细节不进正文、一律链出去」原则 | 解决「同一件事在几个文件各写一遍，改一处忘了另几处」；没有它：README / handover 与总纲、ADR、`install.md` 各说各话，交接人读到哪份算哪份 |
| 4 | ADR 一览表 | 解决「9 条 ADR 逐个点开才知道定了什么」；没有它：交接人不知道哪些决定已板上钉钉、不能重开 |
| 5 | 陈旧状态行回填（总纲 + 六份子 spec 头部 + 根 `AGENTS.md` 那一句） | 解决「按『待开』『未开工』去找、以为活没干」；没有它：交接人找不到已经存在的 issue，重复开工 |
| 6 | 「活怎么交代出去」动线（`handover.md` §7） | 解决「非技术 owner 不知道需求怎么提、合并要谁点头、进度去哪看」；没有它：交接卡在「找不到人接着干」 |
| 7 | 交接主线落 ADR | 解决「接手人是谁、先推 S2 还是先上线」被反复重开；没有它：下一个 agent 会按「先上线」排序，让 owner 把同一个决定再拍一遍 |

## 7. 自定细节

**体例与落点**

- 新文件命名 `docs/handover.md`（与 `docs/specs/`、`docs/decisions/` 平级）。
- README 只走非技术主线；技术入口只放链接 + 一句说明。
- README「前因后果」节**上限 10 行**——超了说明写成了技术文档。
- handover 的上线步骤写「人话版」，命令与细则以 `deploy/install.md` 为唯一真相源。
- 术语表**按正文首次出现顺序排**（不按字母、不按重要性）。
- 一览表排在决策记录规则页的「载体分工」之后，每行只放「链接 + 状态 + 一句话」。
- 本份的实施（写文档）另开 issue，从段二进；不与此 spec 合并进同一个 PR。

**口径与判据（未写死的数字都是 agent 定的，owner 扫一眼即可）**

- 「10 分钟看懂 / 10 分钟内能复述」是 §3 与 §6 的可验门槛；找不到真人读时，退化为「首屏 + 六节内说清四件事」。
- 一览表状态列**与各 ADR 文件头部的 `状态` 逐字一致**；已被取代的照文件头部写「已被取代」。
- 状态口径以 **issue 标签**为唯一真相源（`gh issue list` 现查），不靠记忆；S1-C 的「受阻」与原因原样带出。
- 上线前置列**总纲 §12.1 的 5 项**，不合并、不缩写。
- §4.4 的 PR 号取自 2026-10-07 的 git log；实施时**对表远端复核**一遍再写。
- 根 `AGENTS.md` 只动第 5 行那一句——它在 `spec-s1a-foundation.md` §2 里是 S1-A 独占目录，动多了会跟那份打架。
