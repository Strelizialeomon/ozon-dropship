## 3. 两层结构（本份的核心决定）

| 层 | 文件 | 给谁 | 到什么程度算够 |
|---|---|---|---|
| 门口 | `README.md` | 任何人，第一眼 | 10 分钟看懂：是什么 / 为什么 / 现在到哪 / 下一步按哪几个键 |
| 内部 | `docs/handover.md` | 接手的非技术 owner | 照着能独立推进：上线、日常操作、S2 要什么、活怎么交代出去 |

技术细节（总纲、ADR、`backend/ARCHITECTURE.md`、`deploy/install.md`）**不进这两层正文**——一律链出去，正文不复述（复述必漂）。

## 4. 要做的事

### 4.1 重写根 `README.md`

节序（非技术主线）：

1. **一句话**：这个系统替谁干什么。
2. **前因后果**（≤ 10 行）：业务背景（10+ 店、日 200–1000 单）、为什么自研（现成 ERP 采购环节全是半自动）、谁拍板；链 Issue #1 全文与 [ADR-build-in-house](../decisions/2026-10-07-build-in-house.md)。
3. **现在到哪了**：S1 六份全部合并、全部「待上线」；上线还缺三件事（真服务器 + 域名、线路实测、真实 Ozon 凭据）。
4. **怎么用起来**：五步梗概 → 链 `docs/handover.md`。
5. **文档地图**：谁看哪份——非技术看 handover；技术看总纲 / ADR / `backend/ARCHITECTURE.md` / `deploy/`。
6. **这个仓怎么干活**：spec-flow 两段流程、ADR、issue 标签，各**一句话** + 指回 `AGENTS.md`（不复述细则）。

### 4.2 新增 `docs/handover.md`

节序：

1. **这个系统是什么**——非技术版前因后果，带一个生活化比方。
2. **术语表**——正文出现的每个内部专名一句话解释（rFBS / FBP / 本土店、中转点 / 货代仓、面单、`posting_number`、采购任务、异常池、凭据保险箱、追踪号回填……）；按正文首次出现顺序排。
3. **现在到哪了**——S1 六份各做了什么 × 状态表 + 上线缺的三件事。
4. **从零上线**——`deploy/install.md` 的「人话版」：要买什么、要准备哪些账号与凭据、每步大概多久、卡住看哪；命令细则**链过去，不复述**。
5. **日常怎么用**——对着操作台页面写（订单 / 采购任务 / 发货 / 映射与报价 / 异常池 / 店铺与凭据）。
6. **S2 要做什么**——总纲 §9·S2 验收清单翻成人话 + 「怎么算干完了」。
7. **活怎么交代出去**——非技术 owner 找人 / 找 AI 接着干的最小流程：需求怎么描述、issue 怎么用、每份交付物合并前要谁点头、去哪看进度。
8. **出了事怎么办**——凭据到期告警、备份与恢复演练、日志在哪、看哪张表。

### 4.3 `docs/decisions/README.md` 补 ADR 一览表

一张表，一条 ADR 一行：链接 + 状态 + 一句话。**状态必须与各文件头部一致**；已被取代的（`go-package-deps` v1）也列，标「已被取代」。排规则页「载体分工」之后，不动规则正文。

## 5. 机制清单

| # | 机制 | 解决什么 / 没有它会怎样 |
|---|---|---|
| 1 | README 重写（门口层） | 解决「第一眼就看过时信息、直接走偏」；没有它：交接人读了 README 以为项目才开工一半 |
| 2 | 新增 `docs/handover.md`（内部层） | 解决「非技术 owner 拿到仓库没法独立推进」；没有它：README 只够给梗概，真上手还得满仓翻 |
| 3 | ADR 一览表 | 解决「9 个文件逐个点开才知道定了什么」；没有它：交接人不知道哪些决定已板上钉钉、不能重开 |
| 4 | spec 元信息回填 | 解决「按『待开』去找、以为活没干」；没有它：交接人找不到已经存在的 issue，重复开工 |

## 6. 验收

- [ ] 找一个没读过本仓的人，只读 `README.md`，10 分钟内能复述「这项目干嘛的、现在到哪、下一步做什么」
- [ ] 只照 `docs/handover.md`，能独立走完「准备账号 → 装服务器 → 建登录账号 → 建店铺 → 录凭据 → 看到第一张订单」，全程不问人
- [ ] `handover.md` 正文出现的每个内部专名，术语表里都有条目（逐个搜一遍对账，列出来）
- [ ] ADR 一览表每行的状态与对应文件头部一致（逐行对账）
- [ ] 全仓搜「待开」「未开工」「实施中」：命中处要么是真待办、要么已改（逐条列出）
- [ ] README 与 handover 正文的技术名词都链到对应文档，未复述细则
- [ ] 非技术 reader 能说清「S2 怎么交代出去」——用 §4.2 第 7 节走一遍

## 7. 自定细节

- 新文件命名 `docs/handover.md`（与 `docs/specs/`、`docs/decisions/` 平级）。
- README 只走非技术主线；技术入口只放链接 + 一句说明。
- handover 的上线步骤写「人话版」，命令与细则以 `deploy/install.md` 为唯一真相源。
- 一览表排在决策记录规则页的「载体分工」之后。
- 本份的实施（写文档）另开 issue，从段二进；不与此 spec 合并进同一个 PR。
