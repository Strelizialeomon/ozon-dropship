# ADR-20261007-repo-layout：一个总仓，backend/ 与 frontend/ 两个子项目，依赖分开

- 状态：生效中
- 日期：2026-10-07
- 决策人：用户（owner）
- 适用范围：仓库结构、依赖管理
- 取代：无
- 被取代：无
- 决策来源：2026-10-07 会话（owner：「前端和后端的库要分开，不要混在一起……一个总仓下面有两个」，并要求参照自己现有项目）

## 决定

- 本仓是总仓，下设两个独立子项目：
  - `backend/`：自己的 `go.mod`；
  - `frontend/`：自己的 `package.json` + `bun.lock`。
- 两边依赖各管各的：**根目录不放任何依赖清单，不建跨端 workspace**。
- `docs/`（spec / ADR / 调研）与总规矩（`AGENTS.md`、`README.md`）放根目录；子目录可各放一份只管本端的指令文件。
- 结构照 owner 现有项目 xhs-analysis（`backend/` + `frontend/` + `docs/`）。

## 依据

- owner 明确要求前后端依赖分开、放在同一个总仓下。
- 前后端同一人维护：同仓便于一次提交两边一起改；依赖分开避免两套工具链互相污染。

## 否决了什么

- 前后端拆成两个独立仓库。
- 根目录统一 workspace、前后端依赖混在一起。

## 接受的代价

- 两个子项目各自安装、各自构建，命令要进对目录执行。

## 允许重开的条件

- 出现第三个需要共享代码的端（例如另一个前端），现有结构放不下。
