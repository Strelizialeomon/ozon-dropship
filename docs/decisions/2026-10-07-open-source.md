# ADR-20261007-open-source：项目以 AGPL-3.0 开源，全仓（含文档与 issue）公开

- 状态：生效中
- 日期：2026-10-07
- 决策人：用户（owner）
- 适用范围：整仓的对外可见性与许可（代码 / 文档 / issue / PR / 仓库设置）
- 取代：无
- 被取代：无
- 决策来源：2026-10-07 会话（owner 点选：许可证 AGPL-3.0；文档与 issue 全公开；与交接线排序「交接先行」）

## 决定

- 项目整体开源，许可证 **AGPL-3.0**（`LICENSE` 为 gnu.org 官方全文）。
- 仓库对公众可见，**含** `docs/specs/`、`docs/decisions/`、issue 与 PR；不做历史重写、不清理提交邮箱。
- 「翻公开」为发布序最后一步：文件就绪、实施 PR 合并后，**owner 点头才执行**。

## 依据

- 2026-10-07 全库 + 全历史扫描实测：无密钥、无真实域名 / IP、无个人信息文件（配置均为占位符）；唯一暴露项为提交历史中的个人邮箱，owner 知悉并接受保留。
- 选 AGPL 而非宽松许可：要挡住「他人拿去做闭源 SaaS」；接受其劝退部分商业采用的代价。
- 文档全公开：仓库完整、文档本身即项目价值；拆私仓要多维护一套仓库并重写全部链接。

## 否决了什么

- **MIT / Apache-2.0**：更宽松、采用摩擦小，但挡不住闭源白嫖。
- **只公开代码、内部文档移走私仓**：省了暴露面，但双仓维护与全量链接重写成本更高。
- **重写历史去掉提交邮箱**：代价大（全部 commit ID 变化）、收益小。
- **本次加 CI**：机制卡未选；将来另议。

## 接受的代价

- 商业设计（总纲、ADR）对外可见；公开后内容可能被索引 / fork，**无法收回**。
- AGPL 会劝退部分商业采用；今后引入新依赖需注意许可兼容（整体以 AGPL 分发，专有 / 不兼容许可的组件不可并入）。
- 提交历史含个人邮箱。

## 允许重开的条件

- 出现必须引入、且与 AGPL 不兼容的依赖或组件、又无替代时 → 重新评估许可形态（走取代）。
- 商业模式变化要求闭源时 → owner 拍板后走取代。
