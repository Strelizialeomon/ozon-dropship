# ADR-20261007-handover-s2-first：接手人是非技术 owner；接手后先推 S2 开发，不先上线

- 状态：生效中
- 日期：2026-10-07
- 决策人：用户（owner）
- 适用范围：项目交接、后续需求优先级、对外文档的读者定调
- 取代：无
- 被取代：无
- 决策来源：2026-10-07 会话（owner 拍板「接手人是非技术的运营 / 老板」「接手后先推 S2 开发，不是先上线」）

## 决定

- **接手人 = 非技术的运营 / 老板**，不写代码。
- 接手后**先推 S2 开发**（多店规模化 + 1688 全自动），**不是先上线** S1。
- 由此定调：项目对外文档（README、交接手册）的主线读者是**不写代码的人**；后续文档改动都按这个读者写。

## 依据

- S1（地基 + 单店端到端闭环）六份 spec 已全部合并，代码侧只等上线前置条件。
- 上线前置 5 项里，当前唯一卡点是 1688「买家自用版」权限——issue #8 因此挂「受阻」（出处：总纲 §12.1）。
- owner 的业务判断：先把多店规模化做出来，比先跑通单店上线更有价值。

## 否决了什么

- 「先上线跑通第一张真订单，再谈 S2」这个顺序。
- 把交接文档写成技术文档（总纲 / ADR / `deploy/install.md` 的复述体）。

## 接受的代价

- 系统真正跑在真实环境的时间被推后；上线前置动作（1688 权限、Ozon 凭据、中转点、服务器与线路、合规）转为并行推进，不阻塞开发。
- 给非技术读者写的文档，技术读者读起来会嫌浅——用「技术细节链出去」解决。

## 允许重开的条件

- 上线前置条件提前齐备，且 owner 判断先上线的收益更大；
- 接手人换成会写代码的人，文档主线读者随之改变。
